# Отчёт об автоматических проверках backend

Запуск из корня проекта: `npm test`. HTTP-тесты запускают локальный сервер на свободном порту, SQLite-тесты создают временные базы. ML-сервис заменён заглушками. Тесты не требуют работающих приложения, ML или Ollama.

1. `DTO validates required fields, types and message length` — проверяет ограничения DTO.
    - 1.1) Недопустимы пустой объект, строковый `userId`, дробный `sessionId`, строковый `orderId`, пустое сообщение, сообщение из 2 или 301 символа, число вместо сообщения.
    - 1.2) Допустимы сообщения длиной 3 и 300 символов при корректных ID.

2. `low confidence requests clarification without generation` — при уверенности 0,3 запрашиваются уточнения, генерация не вызывается.

3. `order intent requires an order and checks ownership before generation` — для категории заказа запрашивается номер при его отсутствии или отсутствии доступного заказа; при доступном заказе данные передаются в генерацию.
    - 3.1) Нет `orderId`; репозиторий не нашёл заказ по паре `orderId` и `userId`; репозиторий вернул заказ.

4. `human agent and message threshold send to operator` — проверяет вызов передачи оператору.
    - 4.1) Намерение `human_agent` с уверенностью 0,9; наличие трёх предыдущих сообщений.

5. `ML gateway rejects malformed responses and propagates failures` — проверяет отклонение некорректных ответов ML и распространение ошибки вызова.
    - 5.1) Число вместо обработанного текста; confidence=2; пустой ответ генератора; имитированная ошибка timeout. Проверка не подтверждает наличие реального тайм-аута в коде.

6. `classification confidence boundaries follow current routing rules` — проверяет текущие ветви маршрутизации для категории заказа и неизвестной категории.
    - 6.1) Confidence 0 и 0,3 — уточнение; 0,3001 и 0,85 — генерация; 0,8501 — запрос номера заказа; неизвестная категория при 0,9 — уточнение. Это фиксирует текущее поведение и не означает, что оно соответствует требованиям.

7. `session creation and reopening use the supplied identifiers` — проверяет создание отсутствующей сессии, повторное открытие закрытой и отсутствие обновления открытой сессии на заглушках репозитория.

8. `ML gateway sends expected payloads and maps successful responses` — проверяет адреса и тела трёх запросов к ML и преобразование успешных ответов. Сетевые запросы заменены заглушкой axios.

9. `HTTP hello returns the expected response` — GET `/hello` возвращает 200 и `hello!`.

10. `HTTP support validates requests before invoking the service` — контроллер возвращает 400 для некорректного тела и не вызывает сервис; для корректного тела возвращает ответ сервиса.
    - 10.1) Пустой объект, сообщение из 2 символов, строковый `userId`, сообщение из 301 символа; корректный запрос.

11. `HTTP orders validates userId and returns only selected fields` — проверяет отклонение некорректного `userId`, вызов сервиса и состав ответа.
    - 11.1) Пустой, нулевой, отрицательный, дробный, нечисловой, SQL-подобный и превышающий safe integer идентификатор; корректный `userId=7`. Скрытые поля заглушки отсутствуют в ответе.

12. `SQLite order repository isolates users and binds SQL parameters` — проверяет запросы заказов во временной SQLite и пример SQL-инъекции.
    - 12.1) Собственный, чужой и отсутствующий заказ; строка `1 OR 1=1` вместо ID; список заказов другого пользователя и неизменность числа записей. Это не проверка HTTP-аутентификации.

13. `SQLite stores sessions and messages and updates session status` — создаёт сессию и сообщение во временной SQLite, считывает их и проверяет обновление статуса. Проверяется первый созданный сеанс; поведение при несовпадении внешнего и внутреннего ID требует отдельной проверки.

## Границы

Аутентификация, роли и rate limiting в backend не реализованы; тесты не подтверждают защиту от подмены пользователя или доступа к чужой сессии. Проверки не покрывают полноценную работу с реальным ML и Ollama, параллельные сообщения, порядок, повторные запросы, реальные сетевые тайм-ауты или безопасное содержимое ошибок в production. Для них необходимы отдельные проверки и, для отсутствующих механизмов, реализация.
